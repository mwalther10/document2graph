## Changes needed in this repo (`document2graph` 0.2.0)

1. ~~`hybrid_chunker_extractor.py` `max_tokens=131072`~~ **DONE.** Measured on `008_Grundlagen`: old setting gave 23 chunks with the longest at **1885 tokens**, silently truncated by any 512-token embedder — a crippled straw-man baseline. Old tokenizer `google/gemma-3-4b-it` is also a **gated** HF repo, so baseline extraction failed without auth. Now `ChunkerConfig(tokenizer, max_tokens, merge_peers)` on `ExtractorConfig`, defaulting to `intfloat/multilingual-e5-large` / 512 → 38 chunks, all in budget.
2. ~~`generate_baseline_chunks` wrote into `raw_texts/`~~ **DONE.** Chunks now land in `baseline_chunks/`; enriched `open()` un-nested.
3. ~~**Graph load API.**~~ **DONE.** `document2graph/graph_store/` holds `DocumentGraph` / `GraphSnippet`, `save_graph` / `load_graph`. The extractor writes `<data_path>/graphs/<name>_graph.json` next to the GEXF and returns the object as `run()["document_graph"]`. Deviation from the original wording: `load_graph` returns a `DocumentGraph`, not a `SnippetGraph` — the raw form's ids are document-local docling refs (`#/texts/12`) that collide across a corpus. `GraphSnippet` is a lossless superset of the node fields, so a reload needs no re-parse.
4. ~~**Promote the Neo4j/`DocumentGraph` layer**~~ **DONE.** Out of `tests/test_document2graph_extractor.py` into `document2graph/graph_store/` (`document_graph.py`, `serialization.py`, `neo4j_store.py`). `global_id()` hashes the document id with the local ref. `neo4j` is an optional extra; the driver is injected, so the store imports without it. Added `ensure_neo4j_constraints()` (the writes MERGE on `snippet_id` with no index before) and flattened `bbox`/`charspan` into scalar properties (a nested map never reached the DB).
5. ~~**Expose provenance uniformly.**~~ **DONE.** Every unit — graph node, `Snippet`, `GraphSnippet`, baseline `Chunk` — carries `provenance: list[Provenance]` with `(page_no, bbox, charspan)`. `utils/provenance.py` adapts both docling shapes (`DocItem.prov` and a chunk's `meta["doc_items"][*]["prov"]`). It maps *every* prov entry, not `prov[0]`: a paragraph stitched across a column break reports both halves (8 of 337 units on `008_Grundlagen`). `Snippet` also gained the `charspan` it used to drop.
6. ~~**Feature flags on `ExtractorConfig`**~~ **DONE.** `PipelineFlags(repair_reading_order, stitch_continuations, assign_regions, recover_captions, filter_decorative_pictures, level_source)`, all defaulting to current behaviour. Applied post-parse. `level_source` is `hybrid` | `typography` (size only) | `docling` (`SectionHeaderItem.level`). The docling document is now cached under `raw_texts/` and reused by **both** extractors (`use_docling_cache`, `refresh_docling_cache`) — `HybridChunkerExtractor` used to convert every PDF a second time.
7. ~~**Test CI.**~~ **DONE.** `.github/workflows/ci.yml` runs `pytest -m "not slow"` on 3.11 and 3.13 for every push and PR; `python-publish.yml` pinned from `3.x` to `3.11`.
8. ~~Declare the undeclared `python-dotenv` and `neo4j`~~ **DONE.** In `dev`; `neo4j` also as its own extra. Dropped `httpx` (imported nowhere) and added floors on `docling`/`docling-core`/`docling-parse`.

### Follow-ups this opened

- **Breaking output change.** `document_id` is now `uuid5` over the document's name for *both* extractors (it was a fresh `uuid4()` per run on the graph side and the raw filename on the chunk side), and `chunk_id` is deterministic too. Any previously extracted `snippets/`, `baseline_chunks/` or Neo4j data has to be re-generated; drop old Neo4j nodes rather than merging into them. `Chunk.filename` now carries the human-readable name.
- Renaming a PDF re-keys it. If the corpus needs to be rename-proof, `document_id_for` becomes a hash of the file's bytes (one line in `utils/ids.py`).
- `SnippetGraph` itself still has no JSON round-trip. Add `to_json`/`from_json` if a consumer needs the raw, document-local form.
- `BaselineExtractor` reads `config.document_type` and never uses it; `DocumentGraphExtractor` ignores `config.chunker`.
